# Accountable business attention
## A. Identity
A-01 · command centre · owner/manager/dispatcher · P2 after customer flow · ACT-01 and source facts · Issues #1/#8 · v1.0 · 2026-10-18. Specified/designed contract; v1 first-pending list exists, current target not implemented/validated.
## B. Business problem
Operators chase waiting work across tools; supplied workflow context, frequency/benefit not measured.
## C. Expected outcome
Identify next accountable decision and blockers without a decorative dashboard. Measure time-to-identify/resolve in operator test; baseline unknown.
## D. Roles and permissions
View scoped attention; source actions require their own authority. No separate create/modify/approve/cancel/delete/override/export powers from this screen; financial/workload views role-filtered.
## E. Entry points
Business opening, return from task, notification and role-specific work view.
## F. Journey
Inspect attention → understand owner/reason → open relevant customer/task → complete or resolve blocker → return with updated queue. No work shows helpful all-clear, not fabricated urgency.
## G. Data
Action IDs, task/customer/location links, deadlines, appointments, unassigned/delayed work, quote/invoice status, workload and clearly defined economic periods.
## H. Integration contract
Input ACT/source facts; validate org/role/freshness. Output attention selection only; no copied customer state. Source command updates workflow; missing source displays unavailable/not zero. Commands audit; queue reads don't. Duplicate refresh no side effect; UI exposes source time/blocker.
## I. Rules
Prioritize commitments/urgency/impact, not arbitrary seed order. Overdue isn't unpaid without a valid due date. Relevant metrics must have decision/source/period; no composite 'business health' score.
## J. Interface
Compact actionable work, one recommended action; appointment/workload support progressively disclosed. Keyboard links/panel focus, labelled mobile nav, source-empty/error/loading/retry states.
## K. Automation
Deterministic queue refresh now design; later escalation only with owner/permission/audit contract.
## L. Edge cases
Unassigned work, unavailable integration, denied finances, no eligible actions, changed record while open and overloaded employee.
## M. Acceptance
Given blocked work, owner/reason is visible. Given denied actor, source action cannot execute. Given no tasks, no invented warning. Given unavailable data, metric not zero.
## N. Verification
Domain queue tests plus real keyboard/mobile/desktop task-identification walkthrough; no current target browser evidence.
## O. Release
Source contracts and representative flow must pass before owner analytics expansion; operator usefulness required.
## P. Risks and alternatives
More summaries can duplicate work. A short manual queue is a valid fallback; retain only information changing a decision.
## Q. Extensions
Workload/at-risk forecasting and opportunities after reliable inputs and evidence.
