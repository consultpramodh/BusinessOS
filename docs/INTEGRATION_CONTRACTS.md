# Cross-capability contracts

All commands include organizationId, record ID/version, actor/permission, event/correlation ID, timestamp, validated input and payload fingerprint; return changed IDs/versions, result or recoverable error. Snapshot before accepting downstream historical scope. Replayed identical command returns original result; event ID reused for different request fails. Durable transactions/outbox are production extensions, not implemented now.

| Contract | Input and validation | Output / consumers | Exception / UI | Audit / dedup |
|---|---|---|---|---|
| Intake received | Channel event/source/contact clues/requirement; normalize, org scope, duplicate review | Independent Enquiry + matching candidates; B/C/ACT/K/M | Ambiguous contact remains unmerged; manual fallback if adapter unavailable | Channel event key; who/source/time |
| Qualification saved | Enquiry version, contact/location/assets/service/owner/eligibility; related customer/asset/permission checks | Immutable snapshot + enquiry qualified event; D/ACT/B | Missing/conflicting fields retain draft; technical/area review becomes blocker | Implemented canonical event/request retry guard, actor/time/version |
| Quote accepted | Quote/version/customer/location/scope/amount/acceptance evidence; validity/expiry/authority/current version | AcceptedVersion + eligible planning action; B/E/F/K/M | Technical review prevents schedule; acceptance may succeed with delivery prerequisite unresolved | Acceptance event+version uniqueness, immutable actor/time/terms; commands planned |
| Appointment confirmed | Eligible scope, job, resources/time/window/location/version; review/availability/conflict checks | Visit/Assignment + confirmation intent; F/K/A | Unknown hours/resource/parts means accountable review; notification failure independent | Booking event key, old/new assignment/time |
| Work closed | Visit/work/time/parts/checklist/safety/completion evidence and reviewer authority | Completion/closeout eligibility + attributable direct costs; G/H/K | Return visit/additional approval/unsafe/no-access not falsely completed | Work event IDs, technician/reviewer/time/source |
| Invoice issued | Reviewed billable scope/accepted snapshot/tax/terms/currency/current version | Issued invoice/job links + delivery intent; B/G/H/K/M | Missing approval blocks; provider delivery error not invoice deletion | Invoice issue key, immutable version and authorized actor |
| Payment reconciled | Provider event/payment/currency/customer/amount and allocations; authenticity/remaining balance | Confirmed/reconciled Payment/Allocation + receipt intent; G/H/K/M/ACT | Pending/refund/dispute/over-allocation explicit; no false collected cash | Provider event and allocation uniqueness, actor/provider/time |
| Message lifecycle | Source event/purpose/recipient/preference/consent/channel/template | Queued/delivered/failed/suppressed Communication; B/K/A | Missing purpose/recipient/required consent blocks; retry visible | Purpose+event+recipient key; each delivery attempt tracked |
| Feedback/future service | Completed relevant work, customer response/service interval and unresolved issues | Feedback issue / owned follow-up / possible opportunity | No automatic positive review; service concern resolved first | Source+purpose+interval uniqueness; no duplicate reminder |

Features publish full A–Q contracts under prompts/features/. This table is shared envelope/cross-feature wiring, not duplicate financial or UI rules. Only qualification/current-address mutation and read-only action evaluation are currently implemented in the experimental foundation. Remaining rows are specifications.
